# 字体设置窗口与弹层输入问题（2026-11-10）

## 已验证的直接原因

安装版字体设置窗口持续收到 `KEY_PRESSED ESCAPE`，约每 30 毫秒一次，期间没有对应的 `KEY_RELEASED`。旧版 Scene 的 Esc 处理器因此调用 `Stage.close()`；移除窗口级关闭处理器后，重复输入仍会使字体列表和颜色面板立即收起。

运行时记录确认，颜色面板收起路径包含 `PopupWindow$PopupEventRedirector.handleEscapeKeyPressedEvent`。这与复选框的 selected/disable 绑定无关。

用户在字体设置窗口内按下并松开一次 Esc 后，日志出现 `KEY_RELEASED ESCAPE`，重复事件停止。随后字体列表保持展开约两秒，颜色面板保持展开约一秒，直到用户主动取消；用户确认字体与颜色均恢复可选。

## 处理与验证

- 移除 Scene 级 Esc 关闭窗口的绑定，保留“应用”“取消”和标题栏关闭。
- 增加鼠标取消“跟随主题”和选择器 Esc 转发的回归测试。
- 字体相关 14 项测试通过，已构建更新后的 Debian 安装包。
- 临时运行时诊断监听已移除。
- 后续修复在字体设置 Stage 的事件分发器入口消费 Esc 按下事件，仅在 Esc 松开时关闭已展开的字体/颜色面板。该入口早于 PopupWindow 的自动收起处理，因此重复按下事件不会再关闭面板；其他键盘和鼠标事件继续使用原有分发器。
- 新增回归测试：向字体列表和颜色面板分别连续发送 60 次 Esc 按下事件，验证保持展开；松键后面板正常收起，设置窗口保留，再次展开也正常。字体相关测试共 15 项通过。

## 当前限制

持续 Esc 输入的最初来源尚未确定。运行环境是 GNOME Wayland，JavaFX 21.0.2 经 X11/XWayland 运行；在应用未聚焦时查询 X11 按键状态，Esc 未处于按下状态。这些信息不足以断定具体是键盘、输入法、桌面合成器还是 JavaFX 的问题。

旧版验证有效的恢复方法：在字体设置窗口内按下并完全松开一次 Esc，再操作选择器。新修复通过在应用边界拦截重复 Esc 按下事件，防止它关闭设置窗口及其选择面板；这修复了字体设置的交互症状，没有消除底层持续输入的来源。
